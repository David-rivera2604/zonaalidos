Manual — Configuración de OneDrive File Picker

Qué es esto: permite adjuntar archivos desde OneDrive personal (cuentas Microsoft) directamente en el control de carga de la Zona de Aliados (botón "Adjuntar desde OneDrive" en la sección de Adjuntos). El archivo elegido se descarga de OneDrive y queda adjunto como si el usuario lo hubiera arrastrado manualmente — no se sube nada a OneDrive, solo se lee/descarga desde ahí.
Alcance de este manual: para habilitar esta funcionalidad en un ambiente nuevo (desarrollo, QA, producción) solo hace falta hacer dos cosas: crear un App Registration en Azure Entra ID, y agregar una llave en el archivo de configuración del servidor (web.config). Ambos pasos se explican a continuación.

1. Crear el App Registration en Azure Entra ID

  1. Entre a portal.azure.com → Microsoft Entra ID → Registros de aplicaciones (App registrations).
  2. Clic en Nuevo registro (New registration).
  3. Complete el formulario:
    CampoQué poner
    NameUn nombre identificable para la aplicación, por ejemplo Aliados (se puede cambiar después).
    Supported account types (combo)Personal accounts only — esta integración es solo para OneDrive personal (MSA), no necesita ningún tenant organizacional. No elegir "Single tenant only" ni "Multiple Entra ID tenants": ese fue justo el error del primer registro de este proyecto (ver recuadro rojo abajo).
    Redirect URI (optional) — combo de plataformaSingle-page application (SPA) — nunca "Web" ni "Public client/native (mobile & desktop)".
    Redirect URI (optional) — campo de textoLa URI exacta del entorno, sin "/" al final, por ejemplo https://localhost:44341 en desarrollo local. Se puede completar aquí mismo (como en la captura de abajo) o dejarlo en blanco y agregarlo después desde "Authentication" (paso 2).
  4. Clic en Registrar.
Punto crítico: el tipo de cuenta admitido debe incluir cuentas personales de Microsoft. Si el registro queda configurado solo para cuentas organizacionales (el tipo por defecto en muchos tenants corporativos), el picker de OneDrive personal falla con errores de autenticación aunque el resto de la configuración esté correcta. Esto fue justamente lo que pasó con un primer App Registration usado en este proyecto — hubo que crear uno nuevo con el tipo de cuenta correcto.

2. Configurar la plataforma "Single-page application" (SPA)

Dentro del App Registration recién creado:

  1. Vaya a Autenticación (Authentication) en el menú lateral.
  2. Clic en Agregar una plataforma (Add a platform).
  3. Elija Single-page application — no "Web".
  4. Agregue una URI de redirección por cada entorno donde corra la app, por ejemplo:
    EntornoURI de redirección
    Desarrollo local (IIS Express)https://localhost:44341
    QA / Producciónhttps://<dominio-real>
  5. Guarde los cambios.
No hay nada que configurar por ambiente fuera de Azure: la aplicación toma automáticamente la dirección desde la que se está ejecutando en cada momento (desarrollo, QA, producción, la que sea). Lo único que cambia por ambiente es que esa dirección tiene que estar dada de alta aquí en Azure (la tabla de arriba) — si no está registrada, el inicio de sesión de Microsoft la rechaza.
Sin "/" al final: la URI debe coincidir exactamente con la dirección del sitio (protocolo + dominio + puerto), que nunca trae barra final. Si se agrega con la barra (https://localhost:44341/) el inicio de sesión falla porque no encuentra una URI de redirección coincidente.
No mezclar plataformas con la misma URI: si esa misma URI ya existe registrada bajo la plataforma "Web" (por ejemplo, de otra integración), Azure rechaza el guardado con el error "Redirect URIs must have distinct values". Cada URI debe existir en una sola plataforma. En la captura de arriba se ve justo este caso: ya existía una URI https://localhost:44341/ (con barra) bajo "Web" de otra integración, y la nueva de "Single-page application" se agregó como https://localhost:44341 (sin barra) — esa diferencia de la barra final es lo que permitió que Azure aceptara ambas sin choque.

3. Agregar el permiso de Microsoft Graph "Files.Read"

  1. Vaya a Permisos de API (API permissions).
  2. Clic en Agregar un permiso (Add a permission) → Microsoft Graph → Permisos delegados (Delegated permissions).
  3. Busque y marque Files.Read. Confirme con Agregar permisos.

El permiso User.Read ya viene agregado por defecto en todo App Registration nuevo — no hace falta tocarlo.

Para cuentas personales (MSA) no hace falta "otorgar consentimiento de administrador": cada usuario consiente el permiso la primera vez que usa el picker, vía un popup de inicio de sesión/consentimiento de Microsoft.

4. Copiar el Application (client) ID

  1. Vaya a Información general (Overview) del App Registration.
  2. Copie el valor de Id. de aplicación (cliente) (Application (client) ID) — es un GUID, por ejemplo 30fad849-3999-46ab-8d1a-ae45ff5b50c6.
Este ID no es un secreto: es un identificador público de la aplicación. Es seguro que quede visible en la aplicación, sin necesidad de protegerlo como una contraseña.
Este es el único lugar de donde sale el clientId: el valor que se agrega en el siguiente paso al web.config es exactamente este mismo GUID, copiado tal cual desde este Overview. No se genera ni se calcula en ningún otro lado — es copiar y pegar.

5. Configurar el clientId en el servidor (web.config)

La aplicación no tiene ningún clientId fijo escrito en ningún lado: lo obtiene del archivo de configuración del servidor. Por eso hay que agregar la siguiente entrada en el web.config del ambiente correspondiente, dentro de <appSettings>:

LlaveValor
OneDriveClientId <add key="OneDriveClientId" value="<el-guid-copiado-en-el-paso-4>" />
Si falta esta llave en el web.config del ambiente (dev/QA/producción), el botón de OneDrive muestra el error "No se pudo completar la selección desde OneDrive".

6. Errores comunes al configurar un ambiente nuevo

SíntomaCausaSolución
El picker no autentica / errores raros de inicio de sesión El App Registration tenía el tipo de cuenta equivocado (solo organizacional). Usar un App Registration con "Personal accounts only" habilitado (paso 1).
Redirect URIs must have distinct values al guardar en Azure La misma URI ya existía registrada bajo la plataforma "Web". Usar una URI exclusiva para la plataforma SPA, sin barra final (paso 2).

Checklist para un ambiente nuevo

  1. App Registration en Entra ID con cuentas personales habilitadas.
  2. Plataforma SPA con la URI de redirección exacta del entorno (sin barra final, sin duplicar en "Web").
  3. Permiso delegado Files.Read de Microsoft Graph agregado.
  4. Llave OneDriveClientId en el web.config de ese entorno, con el Application (client) ID del registro.
  5. Probar el botón "Adjuntar desde OneDrive" y confirmar que el picker abre, lista archivos reales y que el archivo elegido termina subiendo por el flujo normal de Adjuntos.
